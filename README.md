# えみちぃ / Emmichy

「わかっているのに、とぼける。ちいかわのことになると、本当に余裕がなくなる。」

Emmy IIの画面を参照した非公式パロディのブラウザ試作。17歳の欧米人ティーン、少しぽっちゃり、ロングヘアー。海外製品の移植を想定した、形を単純化した欧米風イラスト。原作のコード・画像・文字ROMはゲーム素材に使っていません。

## 起動

Node.js 22以降で、フォルダを開いて次を実行。追加パッケージ不要。

```powershell
npm start
```

http://127.0.0.1:1984 をブラウザで開く。API利用料0円、標準動作にインターネット不要。終了はターミナルで Ctrl+C。

## 遊び方

最初の送信から約5分、または18往復でエンディング。進行中の返答があれば完了後に帰ります。アニメを観るために帰る通常版と、映画の話で盛り上がっている場合のリピート鑑賞版があります。再読み込みでも同じタブでは経過を保持。「コンニチハ」で新しい5分の会話を開始し、名前と好みは保持します。

入力はカタカナ・ひらがな推奨。主要な漢字語は意味判定にも使いますが、画面には未対応の漢字を `?` と表示します。汎用的な漢字の読み変換やローマ字入力変換は未実装。現代のIMEで入力できます。

- `ボク ノ ナマエ ハ タロウ` → `ボク ノ ナマエ ハ？`
- `ネコ ガ スキ` → 別の話 → `ネコ ガ キライ`
- `残業で疲れた` → 働きすぎ → シーサーへの心配
- `資格の試験が不安` → `どうして？`（話題を保持）
- `旅行したい` → 島 → 映画ちいかわ
- `シーサー ガ シンパイ` → 別の話 → `ダイジョウブ`
- `映画ちいかわ`（映画への興奮、表示が速くなる）
- `チイカワ イガイ ノ ハナシ`（別のキャラクターへ逃げる）
- `17 * 23`（ちゃんと計算してからグッズに結びつける）
- `バイバイ` → `コンニチハ`

会話・記憶はブラウザのlocalStorage。最大40発言・好み24件。保存不可ならそのセッション内だけ動作。アソビカタ内に会話保存・記憶初期化があります。ブラウザやポートを変えると保存場所が変わります。

## 会話の方式

1. 名前、好み、矛盾、反復、計算を判定する。
2. 日常語の連想辞書を重み付きで照合。「試験／資格→シーサー」「旅行／海→映画」の経路を選ぶ。
3. 前の話題を保持。「どうして？」「もっと」にその話題で返す。
4. シーサーの不安・映画の興奮を保存。話題が変わっても感情が残る。励ますと不安が下がる。
5. ちいかわへの脱線として発話する。

これは汎用的な意味理解ではありません。辞書にない言い換え・複雑な否定・文脈は取りこぼします。「今の生成AI並みの頭脳」を自由会話全般に求める場合は、下記のローカルLLMが必要です。標準モードはその面白さを限定した話題で検証する試作です。

## 任意：無料のローカルLLM

Ollamaを別途導入し、手元のPCで動かせるモデルを取得してから：

```powershell
ollama pull qwen3:4b
$env:EMMICHY_MODEL = 'qwen3:4b'
npm start
```

Ollamaの既定の `127.0.0.1:11434/api/chat` だけに接続。有料APIは呼びません。モデルのダウンロードと実行にはディスク・RAM・電力が必要。4bは導入候補であって日本語会話品質を保証するものではありません。実モデルでの品質確認は未実施。環境変数を消して再起動すれば標準モードに戻ります。

```powershell
Remove-Item Env:EMMICHY_MODEL
```

名前、矛盾、計算、時事、映画・連載の固定演出はルールを優先。それ以外はLLMに最近8発言と記憶を渡します。20秒で打ち切り、失敗時・長文・漢字混入・ちいかわ要素のない出力はルールに戻します。品質の厳格さとフォールバック頻度には調整余地があります。

仕様参考：[Ollama Chat API](https://docs.ollama.com/api/chat)、[Qwen3モデル一覧](https://ollama.com/library/qwen3)。

## 時事の更新

`src/topics.js` の `news` を編集。確認日、出典、事実、開始日、有効期限、創作の返答を分けています。自動ニュース取得は行いません。シーサーへの不安は2026-10-04時点のユーザー指定によるファン設定。一次投稿を直接取得できなかったため、具体的な連載の結末は組み込みません。

## 画面再現の到達点

内部Canvasは640×200、縦2倍相当の8:5表示、RGB各1bitの8色、文字もビットマップ。人物画は248×168へラスタライズし、8色のディザに変換。絵柄を維持し、人物部分をさらに半分へ落とす処理は撤去しました。元の高解像度画像がそのままゲーム画面へ出ることはありません。

フォントは自作5×7を8×8セルに配置した近似です。原機文字ROM、原作の文字アトリビュート制約、CPU速度、描画順序、好感度の正確な閾値までは再現していません。厳密なエミュレータではありません。添付画像の黒地・人物左／会話右・下の入力行という構成が基準です。

## 開発

```powershell
npm test
```

`src/engine.js`：記憶と基本会話。`src/associations.js`：日常語→作品話題の橋渡し。`src/topics.js`：ファン心理と時事。`src/session.js`：5分／18往復とエンディング。`src/font.js`：自作文字。`src/app.js`：描画と操作。`server.mjs`：ローカル配信と任意のLLM接続。

調査結果は `docs/research.md`。画像の作成条件は `docs/art-direction.md`。

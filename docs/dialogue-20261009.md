# 名前を拾う反応と、同じ話題の続き

ユーザーの2026-10-08〜09の試遊指摘をこの1セッションで実装。自動Relayや別Workへの送信なし。

- レオリオはHUNTER×HUNTERの人物。表示の一般辞書が「レオ」「リオ」に分けていたため、名前の辞書で一語として保護した。かな・半角・空白違いも扱う。
- 送信直後に名前を拾い「ヒソカ！」「ハチワレ！」などを表示。AI待機中の一般相づちより先に反応する。プレイヤーの原文は書き換えない。
- 人物・用語・主要ゲームなど562項目。内訳はちいかわ50、ハンター198、ジョジョ150、主要ゲーム名・別名95、他作品の主要語69。別にSteam公式ストアから2,970タイトル。既存27作品のタグも利用する。詳細・取得元は name-data-20261008.json / game-names-20261008.json。
- 現在の作品とちいかわには、一文字の置換・脱字・重複・隣接入れ替えを扱う。「桃が／ももが」→モモンガはユーザー指定の聞き間違い。短い脇役名は一般語の誤反応を抑える。聞き間違いを原作事実や入力の訂正にしない。
- 本文を短い完結した文に分け、最初の続きは4秒、次は5秒待つ。キー・入力変更・IMEを感知して停止し、最後の操作から6秒待つ。新しい送信、終了、リセットで旧続きを破棄。未表示の続きは保存せず、続きのためのAI通信を増やさない。
- ちいかわに近い言葉があると少し強引に挟むが、手がかりがなければ現話題を続ける。開幕で1プレイ一度のちいかわへの言及を保証。拒否と深刻な相談を優先。
- 日本への訪問は短期間だけ、生活知識は主に耳知識で少し勘違いする設定をSPEC、公開AIの指示、ローカルAIの指示へ記録。
- 入力欄の直下に「カタカナに直さず、ふつうの漢字・かな交じりで書いてね。」を常時表示。判別とAI通信は入力原文を使い、カタカナの読みは画面表示用。

## 検証と限界

ゲーム109件・中継27件のテスト成功。名前反応の順序、入力原文保持、近似、拒否、レオリオの読み、続きを入力中に止めること、IME中の停止、6秒後の再開、新話題での破棄、未完発言を保存しないことを確認。Workerのdry-run bundleも成功（492.38 KiB、gzip 107.30 KiB）。

実画面では島二郎の水流への返答後、入力開始で続きを待たせ、その後「普段はお店にいる人なのに…」「次にお店の場面を見ても…」へ続くこととレオリオ一語表示を確認。playtest-20261009-dialogue-local.png / playtest-20261009-names-local.png が証跡。

初稿は水流の感想を言い換えて繰り返していた。実画面で見つけ、店主としての普段との落差へ修正した。辞書の初稿は普通の「〜がした」を脇役ガシタと誤認。短い補助名の近似条件を絞り回帰テストを追加。

全漫画・全ゲーム・全表記の完全網羅ではない。名前の存在を扱う辞書で、全キャラの事実DBを作ったという意味でもない。重要な名前の読みは手動で保護し、その他の読みには一般辞書による推定が残る。Steam取得は30ページ後のHTTP 429で停止し、それ以上リトライしていない。公式ページに読み取れる名前がない箇所は主要名を手動登録。ゲームカタログの価格や売上は使わない。

実LLMによる新しい会話品質の比較試遊は未実施。モデルが指示通り自然に話題を広げるか、近似がしつこすぎないか、未登録の名前・読みの修正は今後の人間試遊で評価する。

## 更新

主要名・別名は src/name-seeds.js を編集。公式人物名再取得は node scripts/build-name-data.mjs、Steamタイトル再取得は node scripts/build-game-names.mjs を明示的に実行。通信失敗・429なら止め、収録範囲を報告する。実行時のカタログ取得はしない。

名前だけを中継へ同期するには node scripts/sync-dialogue.mjs ../game-llm --names-only。中継の指示へ渡すのはサーバー辞書に一致した一項目だけ。全辞書やブラウザの自由な文章をsystemへ入れない。

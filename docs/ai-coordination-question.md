# Claudeの開発手法管理セッションへ渡す質問

EmmichyでGPT・Claude・Geminiの間の資料収集と検品を、人間が毎回コピーして中継せずに行う方法を検討してください。

前提：
- Director・実装・採用・テスト・公開の最終判断は、今のOpenAI Codexセッションだけが担当します。別Directorや自動Relayを再開する目的ではありません。
- ClaudeとGeminiはPC／スマホのWeb・アプリで使え、Antigravity上でも起動できます。このPCのClaude Codeはインストール済みですが、Codexから調べた時点では未ログインでした。Gemini CLIは見つかっていません。
- 既存の利用枠を使いたいです。チャットの余り枠とAPI課金を区別し、無断で有料APIや新しい契約を追加しないでください。
- リポジトリはmukkii-game/emmichy、Windowsの作業場所はE:\ゲーム企画\Emmy。
- 調査担当は、docs/chiikawa-research-brief.mdに従い、research/chiikawa/gemini.csv または claude.csv へ固定22列の成果物を置き、排他制御付きスクリプトでSTATUS.mdへ結果を追記します。原作本文の全文転載や、自動の知識採用・コード改変・公開はしません。

聞きたいこと：
1. 現在使える正式な機能で、CodexからAntigravityのClaude／Geminiへ一回の限定調査を起動し、成果物と完了通知を受け取れますか？ CLI、MCP、共有フォルダ、GitHubのどの方法が実行可能ですか？ 想像上のAPIを提案せず、確認済みの機能と必要な初期設定を示してください。
2. 最初のログイン・権限設定だけ人間が行い、以後は共有ファイルで「収集→他モデルの出典照合→Codexへ返却」を進められる、最小構成を作れますか？ Windowsでの具体的な手順、ジョブ入力・成果物・完了・失敗のファイル形式をください。
3. 既存のClaude／Gemini契約の枠を使える経路と、別途API課金になる経路を明確にしてください。枠切れ、429、認証切れ、返答停止時には止まり、有料の代替へ勝手に切り替えない設計にしてください。
4. 初回は10〜25件のデータだけを対象に、成功を確認できる小さな実証手順をください。無期限の監視、定期起動、相互に何度も呼び続ける構成は避け、回数・時間・担当を決めて実行します。

回答には、推奨構成一つ、必要な設定、実行できるコマンドまたは機能名、ジョブ／成果物の例、費用枠の扱い、現時点で出来ないことを含めてください。元のゲーム開発セッションを唯一の採用・公開担当として維持します。

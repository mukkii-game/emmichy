# Geminiへの追加依頼：件数追加より出典の修正

## 目的と前提

docs/chiikawa-research-brief.mdとresearch/chiikawa/codex-review.mdを読み、あなたの300行をゲームに安全に使える資料へ整えてください。質問・人間の確認待ちは不要です。元のgemini.csv、Claudeの成果物、ゲームコードは変更しません。既存の調査内容を活かし、全件を最初から調べ直しません。

推奨はAntigravityで利用できるGemini ProのHigh。高い推論設定でも、本文を読めなければ確認済みにしないでください。

## 必ず直す点

現在182行の根拠がepisodeHistories.jsonです。この資料は話数・題名・画像ファイル名の目次で、個々の場面、台詞の話者、食べ物を食べた人物、動機、人物関係の本文ではありません。特にscene 90行に共通で追加した「日常や討伐、美味しい食べ物の場面」は各話の確認済み事実にしないでください。

1. 全300行を、主張と根拠の対応という観点で分類する。目次から直接確かめられる題名・番号は残す。内容が題名・番号だけならsceneの内容を読んだと扱わない。
2. 目次やトップページしか根拠がない具体的場面・関係・口癖・音楽の主張は、個別の本文URLへ付け替えるか、確認状況と事実を修正する。証拠が足りなければ保留・不明にする。感想と連想は原作事実から分離する。
3. 実際の新規閲覧は重要30事実まで。うさぎの掛け声、歌と用途、島二郎と食べ物、キャラクター間の関係、日常の会話に接続しやすい食べ物を優先する。残りは未確認として整理し、件数の埋め合わせをしない。
4. 最新漫画は公開日時・個別投稿・本文が読めた最後の範囲だけとする。連載アカウントや放送予定の一般情報を「今話題の漫画の展開」の代わりにしない。

## 納品

- research/chiikawa/gemini-revised.csv：元依頼と同じ22列。修正した全データ。必要なら行数を減らしてよい。
- research/chiikawa/gemini-audit.csv：固定列 `ID,判定,問題,修正内容,照合URL`。元300行について1行ずつ。判定は `維持 / 修正 / 保留 / 削除`。不明は不明。
- 22列ファイルをscripts/check-chiikawa-csv.pyで検査する。実行不可なら未実行と記す。
- scripts/chiikawa-research-status.pyで実際の修正版行数と「追加検品完了／保留件数／未確認理由」を追記する。

300行すべての判定が揃い、確認済みと未確認を分けた修正版が納品できれば完了。追加調査が30事実に達する、またはアクセス制限がある場合は、確認できた分で止め、未確認を隠さない。最終報告は修正版行数・修正件数・保留件数・個別本文を確認した事実数・機械検査結果だけを短く記す。Codexが統合する。

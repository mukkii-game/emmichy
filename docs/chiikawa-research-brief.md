# ちいかわ知識収集・検品の依頼書

Emmichyは、ちいかわが大好きで、日常の言葉から嬉しそうに話を始めるキャラクターとのWeb会話ゲーム。開発と最終採用は現在のEmmichyセッションで行う。この依頼は資料の収集と検品だけ。コードの変更、公開、API契約、自動Relayはしない。

## 分担と費用

- SolまたはこのDirector：収集範囲、情報の粒度、矛盾の判断、採用可否。
- Luna：指定した公式ページから、形式の決まった事実・URL・位置を抽出。出典を読まずに記憶で埋めない。
- Gemini／Claudeを手動で使う場合：下のA〜Cから一つの範囲を担当し、別モデルに結果の検品を依頼。同じ調査を全員に重複させない。利用枠の余りとAPI無料枠は別なので、この依頼のために有料APIを追加しない。
- Python：既知の公式目次取得、形式、重複、日付、出典欠落の検査。原作との意味の一致を証明する道具ではない。
- GitHub Actions：手動の検査だけ。モデル呼び出し、定期収集、自動マージやゲームへの自動採用なし。

OpenAIのモデル選択ガイドも、細かい抽出はLuna、複雑な判断と改訂を伴う成果物はSolという使い分けの目安を示す。これはモデル性能の保証ではなく、この作業に対する分担案。
https://developers.openai.com/api/docs/guides/model-selection

## 調査の分け方

A. 映画：公式のあらすじ、人物紹介、作者・制作陣インタビューを優先。人物、目的、行動、持ち物、食べ物、対人関係を1件1事実で整理。まず30〜50件。物語の秘密は別枠。

B. 過去の場面：まず「ほめられリボン」「黒い流れ星」「拾魔」「草むしり検定」「お酒の資格」「シーサーの資格」などの所在を確かめ、実際に一次資料を読める場面を10〜20件。公式目次の題名だけを見て展開を補完しない。「有名」「話題になった」とする根拠も、場面の事実とは分ける。

C. 最新の漫画連載：作者の公式投稿を日付付きで確認。最後に確認できた投稿URLを必須にする。アニメの再配信日や古いニュースを現在の漫画の展開と扱わない。取得できなければ `unverified` として止める。検索結果の断片だけで結末を作らない。

公式の入口：
- https://chiikawa.toho-movie.jp/atm/index.html
- https://chiikawa.toho-movie.jp/atm/characters.html
- https://www.anime-chiikawa.jp/
- https://www.anime-chiikawa.jp/json/episodeHistories.json

## 返すデータ

JSONで、各項目に次を付ける。最初は10件を見本として返し、形式と根拠を確認してから範囲を広げる。全文転載や漫画画像の収集は不要。

`id / medium / arc / title / subject / predicate / object / shortFact / sourceUrl / sourceLocator / publishedAt / checkedAt / evidenceType / verificationStatus / spoilerLevel / aliases / associationCues / emmiFeeling / forbiddenInference`

- `shortFact`：原作・公式で確認した短い要約。誰が何をしたかを曖昧にしない。
- `sourceLocator`：話数、投稿日時、ページの見出しなど、別の人が確認し直せる位置。
- `verificationStatus`：本文確認済み、題名だけ、二次資料のみ、未確認を区別。
- `associationCues`：日常語からつなぐための創作の連想。例「プリン→甘い物→ラッコ」。原作でプリンを食べたという事実に変えない。
- `emmiFeeling`：本人の感想・想像。例「一緒におやつを選びたい」。原作の台詞として扱わない。
- `forbiddenInference`：誤りやすい接続。例「島二郎の店のカツカレー・貝汁」と「島のフルーツパフェ」を同じ調理場面にしない。
- 不明な日付や位置は推測せずnull。一次資料が見られない項目は採用保留。

## 検品担当への依頼

まず各事実が引用元に存在するか確認。次に人物・行動の主語、漫画と映画とアニメの違い、現在と過去、公式と二次資料、事実と感想、ネタバレを点検する。モデルが同意しただけでは確認済みにしない。誤り・矛盾・保留を行ID付きで返す。

## 採用時の使い方

承認済みだけを共有の関係データへ取り込む。全資料を毎回LLMに送らず、今の対象・質問・直前の話から上位2〜3件を選ぶ。未知の場面でも、確認済みの好きな点や本人の感想で会話を続ける。プレイヤーの訂正はユーザー情報として記憶し、原作の正本を自動で上書きしない。

現在の土台は認識用182語と関係25件。重なりのある別の指標で、合算しない。全場面の網羅は未完了。2026-10-11確認では最新漫画本文は取得できず、9月30日の報道だけで「今の展開」を断定しない。

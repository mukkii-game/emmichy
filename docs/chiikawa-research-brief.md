# Gemini・Claudeへの依頼：Emmichy用ちいかわデータベースを作成してください

## 目的

えみちぃがプレイヤーの言葉からちいかわの話を正確に広げるため、名前・関係・場面・口癖・音楽を調べてCSVにしてください。Codexはこの資料で、ゲームへ採用する事実、会話への接点、誤りを防ぐ境界を判断します。

この依頼書を読んだら質問を挟まず、以下の範囲を調べ、CSV・検査・完了記録まで行ってください。不明は「不明」。アクセスできない範囲は理由を残して完了します。件数のために作り話を足さないでください。

## 調べる範囲と出典

人物、別名、性格、人物関係、作者・声優・制作関係者、食べ物、道具、場所、資格、章、具体的な場面、短い口癖と話者、曲名と用途・歌唱者、映画、確認できる最新漫画連載を対象にします。日常の食べ物・気持ち・行動などからつなぐ連想も付けます。

出典の優先順位は **一次資料 → Wikipedia → 個人のまとめ**。一次資料は公式原作投稿、公式アニメ／動画、公式映画、作者・制作陣の公式発言、公式商品など。商品に書かれた名前は名前の根拠であり、原作場面の証拠ではありません。Wikiや個人のまとめだけの情報は「二次のみ」。一次の本文が見られなければ「一次本文確認」にしないでください。

入口：
- https://www.anime-chiikawa.jp/ と公式動画・お知らせ。
- https://www.anime-chiikawa.jp/json/episodeHistories.json （番号・題名だけの目次）。
- https://chiikawa.toho-movie.jp/atm/index.html
- https://chiikawa.toho-movie.jp/atm/characters.html
- https://chiikawamarket.jp/
- 上記公式サイトがリンクする作者本人の公式投稿。

最新連載は、実際に読めた最後の投稿URL・日時・確認日を限定してください。古い報道やアニメ更新を現在の漫画の展開にしないでください。「話題の場面」は出来事の根拠と、話題になった根拠を分けます。

映画は公式に公開済みの人物・設定・予告・制作情報まで。未公開の本編を見たことにせず、原作と映画で同じ展開になると決めつけません。特に確認してほしいものは、セイレーン／人魚、ヒトハ／フタバ、あのこ、島二郎、ナガノ、トクマルシューゴ、チャルメラ、オリオンビール、胸に付ける手作りのちいかわを話題にしやすい人物・物・食べ物の関係です。手作りの飾りはえみちぃの設定であり、原作の事実には追加しません。

## 作るCSV：列名を固定

UTF-8 CSV。ヘッダーは以下の22列をこの順番で使ってください。1行1事実、同じ人物でも別の事実は別行です。

```csv
ID,名前,種類,媒体,出典区分,確認状況,確認日,本文位置,短い事実,関係の主語,関係,関係の対象,別名,特徴タグ,日常の接点,接続しやすさ,評価理由,えみちぃの感想案,混同禁止事項,ネタバレ,公開日,URL
```

- ID：安定した英数字。例expression:usagi:yaha。担当名をIDに付けない。
- 種類：entity / relation / scene / expression / music / item / place / person / arc / latest。
- 媒体：manga / anime / film / official-goods / cross-media。
- 出典区分：一次資料 / Wikipedia / 個人まとめ / 不明。
- 確認状況：一次本文確認 / 二次のみ / 不明。
- 確認日・公開日：YYYY-MM-DD。公開日が分からなければ不明。
- 本文位置：話数、投稿日時、公式ページの見出し、商品名など再確認できる位置。
- 短い事実：180文字以下の自分の要約。確認していない出来事は不明。
- 関係の主語／関係／関係の対象：誰が何をするか。例「うさぎ／掛け声／ヤハ！」。
- 別名／特徴タグ／日常の接点／混同禁止事項：複数の場合は ` | ` で区切る。近似語を公式名にしない。
- 接続しやすさ：1〜5。5は日常会話の多くの言葉からつなげやすい、1は特定の質問でだけ使いやすい。これは調査担当の設計評価であり、原作の強さではありません。評価理由も書く。
- えみちぃの感想案：この子自身の創作の感想・想像。原作の台詞や出来事にしない。
- ネタバレ：none / minor / major / 不明。
- URL：実際に確認したページ。不明な列は空欄ではなく「不明」。CSVの引用符処理は標準ライブラリ等を使い、セル内改行は使わない。

必ず検品する例：ヤハ！はうさぎの掛け声。ちいかわ／ハチワレの口癖や確認済みのOP曲名にしない。ひとりごつはTVアニメのEDでハチワレ歌唱。島二郎の店のメニュー、調理担当者、島のフルーツパフェを混同しない。日常の「プリン→甘い物→ラッコ」は連想であり、プリンを食べた原作場面を作らない。

## 置き場所と分担

リポジトリmukkii-game/emmichy。このPCでは `E:\ゲーム企画\Emmy\research\chiikawa\`。

- **Gemini：広く、件数重視。** 全対象を広く集めて `research/chiikawa/gemini.csv`。目標300行。人物・用語・物・関係・場面・口癖・音楽・映画を一つの種類に偏らず収集する。
- **Claude：同じ範囲を深く。** 主な人物・口癖・曲・混同しやすい関係・代表的な場面を本文位置まで掘り、タグ、接続しやすさの理由、混同禁止事項を充実させて `research/chiikawa/claude.csv`。目標150行。Geminiのファイルを読める場合は比較の手がかりにしてよいが、元資料を独立確認する。
- 自分のCSVだけを書く。相手のCSV、ゲームのコード、main/public、既存の実行用データは変更しない。統合と食い違いの確認はCodexが両方を読んで行う。

既存の自分のCSVに途中成果があれば保持して続け、同じIDを重複追加しません。CSVのヘッダーだけなら未着手です。最初に自分の担当名を判断し、GeminiはGemini、ClaudeはClaudeの納品先を使ってください。

共有フォルダへ書けるAntigravity／CLIを推奨します。別環境でGitHubへ書ける場合は担当専用のcodex/chiikawa-research-gemini／codex/chiikawa-research-claudeブランチに成果物を置き、完了時にブランチ名を報告してください。閲覧しかできないWeb版なら、同じファイル名のCSVと状態行を添付して納品し、実際には保存していないローカルパスを「保存済み」と報告しないでください。

## 完了条件

まず10行で形式を確認し、以後25行程度ずつ追加します。Codexや人間の確認待ちは不要です。付属の `python scripts/check-chiikawa-csv.py research/chiikawa/gemini.csv`（Claudeは自分のファイル）で検査してください。

目標件数に達し、22列がすべて埋まり、各行の名前・種類・媒体・短い事実・確認状況・URLが揃い、機械検査に通ったら完了です。「不明」や「二次のみ」の行を一次本文確認の件数へ数えないでください。資料制限で目標に届かなければ、確認できた分を納品し、未確認範囲と止まった理由を状態に書いて完了します。

名前だけ・全項目不明の行で目標件数を水増ししません。件数はヘッダーを除いた行数で、目標に達しても根拠のない行は完成扱いにしません。Pythonを実行できない環境では、22列・空欄・重複ID・CSVの引用符を自分で確認して納品し、機械検査を「未実行」と報告します。アクセス権やログインがない場合も、依頼者へ質問して待たず、確認できた範囲と制約を残します。

## 禁止

他社作品の文章・漫画・絵・歌詞を丸ごと写さないでください。短い事実要約、関係、確認できる数値、必要最小限の短い口癖だけを扱います。記憶や推測で穴を埋めず、不明と書いてください。未確認の最新話・動機・因果・台詞の話者を作らないでください。新しいAPI契約、有料サービス、自動Relay、無期限の相互呼び出し、ゲームへの自動採用はしません。

## 終了時の状態記録

`research/chiikawa/STATUS.md` に「誰が・何件・止まった理由（なければなし）」を1行追記します。共有状態を同時に書かないため、必ず次のスクリプトを使ってください。

```text
python scripts/chiikawa-research-status.py --agent gemini --count 300 --reason "なし"
python scripts/chiikawa-research-status.py --agent claude --count 150 --reason "なし"
```

件数は実際の納品行数へ置き換えます。スクリプトは書き込みを排他制御します。実行できなければ自分の名前のSTATUS.pending.txtへ状態行を保存し、最終報告にその理由と行を添えてください。相手の状態行を消さないでください。

最後に、CSVの場所・全行数・一次本文確認の件数・不明の件数・検査結果・残る調査範囲だけを短く報告してください。統合・矛盾の判断・ゲームへの採用はCodexが担当します。

Codexは受領後、両CSVの形式を検査し、同じID・同じ人物の関係を比較します。食い違いは元資料を再確認し、解消できなければ保留します。採用・保留・重複とその理由をresearch/chiikawa/codex-review.mdへ記録し、採用した事実だけを既存の実行用データへ変換します。調査CSVをそのままゲームへ読み込ませません。
